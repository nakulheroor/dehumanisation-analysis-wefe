CSV Schema and Coding Criteria (Explicit German Keyword Version)

1) Purpose
This coding framework extracts sentence-level indicators from German newspaper text to identify:
- harmful events,
- affected targets,
- alleged perpetrators,
- attribution/source patterns.

One row in the CSV = one sentence that matched at least one event rule.

2) Column Definitions
- journal: outlet name (e.g., SZ, Spiegel, Zeit, TAZ)
- file: source filename
- sentence: original sentence text
- events: list of matched event categories
- targets: list of matched target categories
- perpetrators: list of matched perpetrator categories
- attributions: list of matched attribution categories
- optional: event__<category> one-hot columns (0/1)
- optional: primary_event = first matched event label

Fallback values:
- targets = [unspecified_target] if no target keyword matched
- perpetrators = [unspecified_perpetrator] if no perpetrator keyword matched
- attributions = [no_explicit_attribution] if no source keyword matched

E) no_explicit_attribution
- assigned when no attribution trigger is detected.

7) Matching Logic Summary
- Sentence-level extraction: rules are applied per sentence.
- Regex pattern matching with German spelling variants (including umlaut alternatives where possible).
- Some rules use proximity constraints (e.g., keyword A within X characters of keyword B).
- Multiple labels per sentence are allowed (multi-label design).
- If no match for target/perpetrator/attribution, fallback “unspecified/no_explicit” labels are assigned.

8) Important Limitations
- Keyword matching does not resolve all pronouns/coreference (“sie”, “beide”, “er”).
- Passive voice can hide actor identity.
- Some terms (e.g., “Bedrohung”) can cause false positives without strict context constraints.
- Output indicates textual mention patterns, not legal responsibility or legal conclusions.
- Manual validation is required for high-stakes reporting.
